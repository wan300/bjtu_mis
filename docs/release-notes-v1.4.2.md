# BJTU MIS Android v1.4.2 更新说明

版本名称：`v1.4.2`；Android 版本号：`9`。上一版本为 `v1.4.1`（版本号 `8`）。

本次更新主要扩展第三方插件的 Android 原生能力，并改善校园邮箱、智能助手和页面加载体验。

## 相比 v1.4.1 的主要变化

### 1. 插件支持更多 Android 能力

- 新增 22 项 beta Android Capability：无障碍事件、窗口节点与操作、已安装应用查询、系统设置入口，以及设备信息、网络状态、电池状态、振动、文件选择与保存、媒体选择、分享、通知、前台定位、日历读取与写入、相机、录音、传感器、生物识别和插件 MIS 会话保活。
- 支持首次或增量审阅后的持久授权；在契约允许范围内，无需每次重复进行宿主确认。需要的 Android 系统权限、系统选择器和前台交互仍须由用户完成。
- 支持持久订阅和后台插件运行，最多同时运行 4 个后台插件；前台页面优先接收事件，后台运行提供持续通知和“全部停止”入口。
- 插件管理页新增后台运行状态、“停止后台运行”“撤销或调整授权”和系统无障碍设置入口。
- 相关 TypeScript SDK、Mock Host、契约、Schema 和开发者文档同步更新；新能力要求 protocol v2；通用原生能力要求 runtime floor 2，会话保活要求 runtime floor 3。

- 插件可在前台申请或续租限时 MIS 会话保活，单租约最多 60 分钟；支持按插件隔离、加密恢复、通知停止及撤销/更新/删除清理。修复单独停止后台插件时保活租约残留导致自动重启的问题。

### 2. 改善校园邮箱正文图片显示

- 邮件详情支持解析 `cid:` 内嵌图片，以及当前邮件的同源 Coremail 附件图片，补全后嵌入正文显示。
- 邮件正文图片不设应用层数量、单张大小和总大小上限，也不设置额外的单张或整封邮件图片加载时限；沿用网络客户端正常的连接和读取超时，单张失败后继续加载后续图片。实际承载量取决于设备可用内存。
- 只请求固定的只读附件端点，禁止跟随重定向，不自动抓取任意外站图片。

### 3. 改善智能助手交互与工具调用

- 调整模型选择器及其操作菜单的显示层级，避免被提示消息或选择面板遮挡。
- 删除模型时先关闭模型选择面板，使确认窗口能够正常显示。
- Agent 工具必填参数改为从当前工具 Schema 获取，减少硬编码校验与真实工具定义不一致的问题，并保留缺失参数提示。

### 4. 优化页面加载与外观交互

- 空教室页面采用只接受最新一次请求结果的加载逻辑，避免较早请求延迟返回后覆盖新筛选结果。
- 将日历、作业、考试和待办的数据聚合收敛到仓库层；部分辅助数据加载失败时仍可返回日历主体，取消请求正确向上传递。
- 统一就业资讯的缓存加载策略，保留网络失败时使用本地快照的处理，并正确传播取消状态。
- 外观切换的撤销提示最多显示 5 秒，并提供主动关闭按钮。
- 拆分课表、成绩、考试、日历、作业、空教室和个人信息等页面源码及共享组件，便于后续维护。

### 5. 修复插件平台与开发工具问题

- 补齐插件平台运行镜像所需的 marketplace Schema 和 Capability Contract Registry，修复校验输入缺失导致有效插件被误判的问题。
- Schema 加载失败时直接报告配置错误，避免产生“未知能力”“未知分类”或错误包大小限制等误导性诊断。
- 修正插件语义版本比较：严格校验版本格式，按规则比较预发布标识，并避免超大数字版本的精度丢失。
- 拆分平台路由，补充旧 API 写接口继续返回 410、举报处理及发布者身份等回归覆盖。

## 升级与兼容说明

- Android 最低版本仍为 Android 8.0（API 26）。正式包需要使用与旧版相同的应用签名，才能覆盖升级。
- 本轮差异没有新增 Room 数据库版本迁移。
- 插件仍以 Manifest v3 / contract_v1 为运行基线；旧 v1/v2 与 P0-A v3 不恢复正常运行，仅保留既有救援路径。
- 插件授权可撤销；持久授权不能绕过系统权限或后台限制，不支持后台定位或后台静默开始录音。邮件发送仍需用户确认，Agent 不自动提交课程平台作业。

## 修复的问题

- Issue #1：修复提示通知遮挡 Agent 模型选择器及操作菜单；删除模型前先关闭选择面板，使确认窗口正常显示。
- Issue #1：补全邮件 `cid:` 与同源 Coremail 附件图片加载。外站图片仍遵守既有安全策略，不自动附带校园认证信息请求任意外站。

## 发布验证

发布前核验 Android 单元测试、插件契约/SDK/模板测试、前端测试、平台测试、正式 APK 版本和签名，并在已连接设备上进行安装启动检查。实际结果随发布检查记录更新；未完成的系统场景不得视为通过。
